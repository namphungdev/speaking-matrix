## Hard constraints

### Rule 1: Frontend and backend are independent apps — never cross-import

`apps/web` (Vite + React) and `services/api` (.NET 10) build separately and
share no package. The API contract between them is **not defined yet**
(`services/api/AGENTS.md` §4) — do not invent endpoints or DTOs to "connect"
them unless the task defines the contract.

- Correct: web reads `src/data/*.js`; API work stays under `services/api/SpeakingMatrix/`.
- Wrong: `import ... from '../../services/...'`, or a speculative `LessonsController` added to feed the web app.

### Rule 2: Persistence lives in Infrastructure — SQL Server + EF Core Code First

Decided in `services/api/docs/architecture/persistence.md`: SQL Server, EF Core,
schema via committed Code First migrations. `DbContext`, EF configuration and
migrations belong to `SpeakingMatrix.Infrastructure`
(`Persistence/ApplicationDbContext.cs`). Never switch provider, never apply a
migration to production. Read `services/api/docs/architecture/` before planning
backend work.

- Correct: `SpeakingMatrix.Infrastructure/Persistence/Configurations/...`, migrations under Infrastructure.
- Wrong: `AddDbContext` in `Program.cs`, a `DbContext` in Api or Application.

### Rule 3: Each layer registers its own services through a `DependencyInjection` extension

`SpeakingMatrix.Infrastructure/DependencyInjection.cs` exposes
`AddInfrastructure(this IServiceCollection, IConfiguration)`; `Program.cs` only
calls it. New layer services go into that layer's extension (Application gets
an `AddApplication` in the same shape when it gains services), not inline in
`Program.cs`.

```csharp
// Correct — Program.cs
builder.Services.AddInfrastructure(builder.Configuration);
// Wrong — Program.cs
builder.Services.AddDbContext<ApplicationDbContext>(o => o.UseSqlServer(...));
```

### Rule 4: Respect the layer dependency direction

Api → Infrastructure (current `ProjectReference`); Application and Domain are
empty shells (`Class1.cs` only). Domain must not reference other layers;
Application may reference Domain only; Infrastructure implements Application
abstractions. Identity (`ApplicationUser : IdentityUser`) stays in
`Infrastructure/Identity`.

### Rule 5: Web UI follows the living spec

`apps/web/specs/prototype.html` is the source of truth for layout, Tailwind
classes and animations (`apps/web/AGENTS.md`, `.clinerules`). Reproduce its
classes; do not restyle.

## Layout families

### Family layered-dotnet — one .csproj per layer

Example module: `services/api/SpeakingMatrix` (solution `SpeakingMatrix.slnx`).

```
services/api/SpeakingMatrix/
├── SpeakingMatrix.slnx                 # build target
├── SpeakingMatrix.Api/                 # Sdk.Web: Program.cs, Controllers/, appsettings*.json
├── SpeakingMatrix.Application/         # use cases (empty shell today)
├── SpeakingMatrix.Domain/              # entities/value objects (empty shell today)
└── SpeakingMatrix.Infrastructure/      # DependencyInjection.cs, Persistence/, Identity/
```

Reference module: `services/api/SpeakingMatrix`.

### Family vite-react-spa — single-page React app

Example module: `apps/web`.

```
apps/web/
├── index.html            # fonts + FontAwesome CDN, #root
├── specs/prototype.html  # living design spec
├── tailwind.config.js    # fonts + glass color tokens
└── src/
    ├── main.jsx          # React root
    ├── App.jsx           # all app state + screen switching
    ├── index.css         # Tailwind directives + custom utilities/keyframes
    ├── components/       # screens and UI pieces (*.jsx, default export)
    ├── data/             # static data modules (named exports)
    └── hooks/            # browser-API wrappers (useSpeech.js)
```

Reference module: `apps/web`.

### How to choose

- Existing module: list its folder and match what is there — `.csproj` per
  layer → `layered-dotnet`; `package.json` + `src/*.jsx` → `vite-react-spa`.
  Never mix shapes.
- New backend code goes into the existing solution's layers; a new service
  (rare) copies the `layered-dotnet` shape. Default family: `layered-dotnet`.
- New UI goes into `apps/web`; there is no second frontend.

## Frontend Architecture

- **Component taxonomy**: screens (`HomeScreen`, `PracticeScreen`) and
  overlays/pieces (`Flashcard`, `SentenceDrawer`, `SpeakingSheet`, `StepGuide`,
  `Toast`) all live flat in `src/components/`, one default-exported function
  component per file. No primitives layer.
- **State**: all app state is `useState` in `src/App.jsx`; children are
  presentational and get data + `on*` callbacks via props. Local UI-only state
  (e.g. `recording` in `SpeakingSheet.jsx`) stays in the component. No store,
  no data-fetching library.
- **Routing**: none — `App.jsx` switches screens with `screen` state
  (`'home' | 'practice'`).
- **Styling**: Tailwind utilities; tokens in `tailwind.config.js`
  (`font-sans` Inter, `font-heading` Space Grotesk, `glass.*` colors); custom
  utilities/animations (`glass-panel`, `liquid-blob-*`, `chromatic-border`,
  3D-flip classes, `slide-up-enter`, `toast-enter`, `wave-bar`) in
  `src/index.css`. Icons are FontAwesome 6 classes loaded from CDN in
  `index.html`.
- **Data**: static sample data in `src/data/lessons.js` and
  `src/data/questions.js` (named exports).
- **Browser APIs**: wrapped in `src/hooks/` with a capability guard
  (`useSpeech.js` checks `'speechSynthesis' in window`).
- **Forms**: none yet.

Do not: add a router or state library without a plan decision; fetch inside
components; use the deprecated `matrix`/`brand`/Nunito tokens; hand-write CSS
that a Tailwind utility or an `index.css` utility already covers.

## Anti-patterns

- Do not cross-import between `apps/web` and `services/api`, or invent API endpoints/contracts.
- Do not register services or a `DbContext` directly in `Program.cs`; use the layer's `DependencyInjection` extension.
- Do not put persistence or Identity code outside `SpeakingMatrix.Infrastructure`, change the DB provider, or apply migrations to production.
- Do not let Domain/Application reference Infrastructure or Api.
- Do not diverge from `apps/web/specs/prototype.html` classes for UI work.
