# speaking-matrix — Coding Conventions

> Generated by np-init on 2026-11-26. Hash-guarded: edit freely — a
> re-init will then write `conventions.md.new.md` instead of overwriting.
>
> **Heading contract (do not change the shape):** every rule heading MUST be
> `## <ID> — <title> [<SEVERITY>]` with SEVERITY one of
> CRITICAL | HIGH | MEDIUM | LOW. Review tooling parses rule ids and
> severities from these headings at runtime.

Apply every rule below when writing or editing source files in this repo.
Architecture-level constraints (folder layout, base classes, DI shape) live in
`architecture.md`; this file covers the **coding-level** rules.

## B1 — No hardcoded values: magic numbers and literal strings get names [CRITICAL]

Any literal with business or configuration meaning lives as a named constant, an
enum member, or a config key — never inline in an expression, an assignment, or
a comparison. Fixed value-sets are real enums, not strings.

```
// BAD
if (amount > 50000) ...            order.Status = "PENDING";
// GOOD
if (amount > Limits.HighRiskThreshold) ...     order.Status = OrderStatus.Pending;
```

## B2 — No secrets or environment-specific config in source [CRITICAL]

Connection strings, API keys, tokens, passwords, hostnames and ports load from
environment/configuration (options pattern, env vars, secret store) — never
committed in code or default config values.

## B3 — Never swallow errors silently [HIGH]

No empty catch blocks, no `catch { return null; }` without logging, no ignored
promise rejections / error callbacks. Handle it, log it with context, or let it
propagate — silence is the only forbidden option.

## B4 — Don't duplicate — reuse the existing helper/pattern [HIGH]

Before writing a utility, mapper, validator, or client, search for the existing
one (`search` / Grep) and extend or reuse it. Copy-pasted variants drift apart
and double every future fix.

## B5 — No dead code left behind [MEDIUM]

Commented-out blocks, unused imports/variables/parameters, and unreachable
branches are removed in the same change that obsoleted them — git history is
the archive, not the source file.

## B6 — Comments: short, necessary, "why" not "what" [MEDIUM]

A comment is at most 3 lines and says something the code cannot: a non-obvious
constraint, a workaround and its reason, an invariant. No file-header
narratives, no doc comments that restate the signature, no step-by-step "what
this does" over code that reads clearly — and never the business change or
ticket that produced the code; that belongs in the commit, the plan, or a
lesson. An exported/public member gets a one-line summary only when its name
alone would mislead.

```
// BAD
/**
 * BrandingPanel renders the branding configuration section of the white-label
 * page. It was added as part of the authentication white-label feature so
 * admins can configure colors, logo and system name …
 */
// GOOD
// Hex only — the theme engine rejects rgb()/hsl().
const COLOR_PATTERN = /^#[0-9a-f]{6}$/i;
```

## B7 — A file exists because it is reused, mandated, or earned — not per type [HIGH]

A type, contract, record, constant group or helper gets its own file only when
it is **reused by two or more consumers**, when the project's placement rules or
the language toolchain **mandate a separate file for that kind** (entry points,
wiring/DI, migrations, tests, one-public-type-per-file languages), or when its
host file has **become hard to read** — a judgment call, not a line count.
Otherwise it lives with its only consumer: a single-use input, output or helper
type beside the code that uses it; a unit's constants in that unit or the
existing group file (still named — B1 stands); no single-implementation
interface unless the reference module has one for that kind. The file count of
the reference module's comparable unit is the anchor: more needs a stated reason
in the plan. A rule that mandates an artifact *kind* mandates the kind and its
location, never one file per member — B7 decides the file. That holds however
the rule is written: a unit spelled as a list of file names
(`{Command.ext, Handler.ext, Validator.ext}`) or a placement row naming three or
more kinds for one unit is a list of **kinds and their folder**, not a file
count.

```
# BAD — one file per type, a folder per kind: 7 files for one unit of work, most under 15 lines
<unit>/  entry point · its input type · its result type · its interface (one impl)
         · its constants · its mapper · abstractions/<port>
# GOOD — the reference module's shape for a comparable unit; single-use types with their consumer
<unit>/  entry point (+ input/result types) · interface only where the reference module has one
<existing constants group> (+1 member)
```

## P1 — Persistence and Identity code live in Infrastructure; schema changes are committed migrations [CRITICAL]

`services/api/docs/architecture/persistence.md` fixes SQL Server + EF Core Code
First. `DbContext`, entity configurations and migrations go in
`SpeakingMatrix.Infrastructure`; migrations are reviewed and committed. Never
change the provider or run a migration against production.

```csharp
// BAD — SpeakingMatrix.Api/Program.cs
builder.Services.AddDbContext<AppDb>(o => o.UseSqlite("Data Source=app.db"));

// GOOD — SpeakingMatrix.Infrastructure/DependencyInjection.cs
services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(connectionString));
```

## P2 — Required configuration fails fast at startup [HIGH]

Read required settings from `IConfiguration` and throw
`InvalidOperationException` naming the missing key — never default silently.
Values (connection strings, `Jwt:*`) come from config/user-secrets
(`UserSecretsId` is set on the Api project); `appsettings.json` keeps them
empty (see B2).

```csharp
// BAD
var cs = configuration.GetConnectionString("DefaultConnection") ?? "Server=.;Database=dev";

// GOOD — DependencyInjection.cs / Program.cs
var connectionString = configuration.GetConnectionString("DefaultConnection")
    ?? throw new InvalidOperationException("Connection string 'DefaultConnection' is not configured.");
```

## P3 — Register a layer's services in its `DependencyInjection` extension [HIGH]

`Program.cs` composes layers (`AddInfrastructure(builder.Configuration)`); it
does not register their internals. See architecture.md Rule 3.

```csharp
// BAD — Program.cs
builder.Services.AddIdentityCore<ApplicationUser>().AddEntityFrameworkStores<ApplicationDbContext>();

// GOOD — Infrastructure/DependencyInjection.cs inside AddInfrastructure(...)
services.AddIdentityCore<ApplicationUser>(o => o.User.RequireUniqueEmail = true)
    .AddRoles<IdentityRole>()
    .AddEntityFrameworkStores<ApplicationDbContext>();
```

## P4 — Infrastructure C# shape: block namespace, usings inside, sealed, primary constructors [MEDIUM]

Infrastructure files (`ApplicationDbContext.cs`, `ApplicationUser.cs`,
`DependencyInjection.cs`) use a block `namespace` with `using` directives
inside it, `sealed` concrete classes, and primary constructors for DI. Match
the file you are editing; Api files follow the ASP.NET template shape.

```csharp
// GOOD — SpeakingMatrix.Infrastructure/Persistence/ApplicationDbContext.cs
namespace SpeakingMatrix.Infrastructure.Persistence
{
    using Microsoft.EntityFrameworkCore;

    public sealed class ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
        : IdentityDbContext<ApplicationUser>(options)
    {
    }
}
```

## P5 — Do not invent API endpoints or web↔API contracts [HIGH]

The contract is undecided (`services/api/AGENTS.md` §4). Add controllers/DTOs
only when the task specifies them; never wire the web app to a guessed URL.

## FB1 — Component files follow reuse and ownership, not the design's layer tree [HIGH]

A screen is one page/view file plus the few section components a developer
would naturally write. A piece of UI earns its own file only when it is
**reused in two or more places**, **owns its own state or data fetching**, or
its parent has grown past what you can read comfortably in one sitting — a
judgment call, not a line count. Single-use cards, dialogs, header rows, form
sections and swatches stay inline in their parent, as local markup or a local
function in whatever form this project's framework uses. Never mirror design
frames, groups or region names into the file tree, and never extract a state
container that wraps a single value.

```
# BAD — one file per design frame
components/BrandingPanel  BrandingSectionCard  ColorSection  LogoIconSection
SystemNameSection  CompanyAccessPanel  RemoveConfirmDialog  SetActiveConfirmDialog …
# GOOD — sections and dialogs inline; one state container because it owns the editor state
pages/BrandingPage   components/BrandingPanel   components/CompanyAccessPanel
hooks/useBrandingEditor   branding.types
```

## FB2 — No design placeholder content in component source [HIGH]

Text, names, numbers, emails, dates, option lists and images visible in a
design frame are **sample data**, not code. Keep two separations, expressed
however this project already expresses them:

- **UI copy** (labels, headings, button text, empty states, input hints) is
  *referenced*, not inlined — through the project's existing i18n catalogue,
  copy/constants module, or content layer. When the project has none,
  establish one per feature and follow the project's own naming.
- **Sample values** — what a field *contains* in the mock, and option lists for
  data-backed fields — never reach component source at all. They belong in a
  dev-only preview source the production build does not import, seeded through
  the project's own state entry point so visual checks still render the filled
  design.

A component must not contain a literal that also appears as a text node in the
design reference. An input hint ("Please select…") is copy; a fake value that
looks real is not.

```
# BAD — a design mock account frozen as the only option, shipped to production
const ACCOUNT_OPTIONS = [{ value: '1011435689', label: '1011435689 I CCCCCCCCCC I VND I đ50,253,172' }]
# GOOD — copy referenced, data from the real source (preview state in dev only)
label={copy.fromAccount} options={accounts ?? previewOptions.fromAccount ?? []}
```

## FE1 — Style with Tailwind + the Liquid Glass tokens; match `specs/prototype.html` [HIGH]

Use Tailwind utilities, the `tailwind.config.js` tokens (`font-heading`,
`glass.*`) and the custom utilities in `src/index.css` (`glass-panel`,
`glass-card-interactive`, `chromatic-border`, 3D-flip classes). Copy class
lists from the living spec. The `matrix`/`brand`/Nunito tokens are deprecated.
New keyframes/utilities go in `src/index.css`, not inline `style`.

```jsx
// BAD
<div style={{ background: 'rgba(255,255,255,.06)', backdropFilter: 'blur(20px)' }} className="font-[Nunito]">
// GOOD — src/components/HomeScreen.jsx
<div className="glass-panel rounded-3xl p-4 chromatic-border">
```

## FE2 — App state lives in `App.jsx`; components are presentational [HIGH]

Shared state (`screen`, `currentIndex`, `isFlipped`, drawer/sheet/toast) is
`useState` in `src/App.jsx`; components receive values and `on*` callbacks as
props. Only UI-local state (e.g. `recording` in `SpeakingSheet.jsx`) stays in a
component. Screens switch by `screen` state — no router.

```jsx
// BAD — PracticeScreen.jsx owns cross-screen state
const [currentIndex, setCurrentIndex] = useState(0);
// GOOD — App.jsx
<PracticeScreen currentIndex={currentIndex} onNext={nextQuestion} onPrev={prevQuestion} />
```

## FE3 — Browser APIs go through `src/hooks/` with a capability guard [MEDIUM]

Wrap Web Speech and similar APIs in a hook module and guard availability;
components call the wrapper.

```js
// GOOD — src/hooks/useSpeech.js
if ('speechSynthesis' in window) {
  window.speechSynthesis.cancel();
  window.speechSynthesis.speak(new SpeechSynthesisUtterance(text));
}
```

## FE4 — Components: default-exported function components, callbacks named `on*` [LOW]

One default export per `src/components/*.jsx`, destructured props with
defaults where a list may be absent (`lessons = []`), event props named
`onX`. Icons are FontAwesome 6 classes (`fa-solid fa-...`).

## File Placement

| Artifact kind | Location per family | Naming pattern |
|---|---|---|
| Entities, value objects, enums | layered-dotnet: `SpeakingMatrix.Domain/` | PascalCase type names |
| Use cases / service interfaces | layered-dotnet: `SpeakingMatrix.Application/` | `I<Name>Service`, `<Name>Service` |
| DbContext, EF configurations, migrations | layered-dotnet: `SpeakingMatrix.Infrastructure/Persistence/` | `ApplicationDbContext`, `<Entity>Configuration` |
| Identity types | layered-dotnet: `SpeakingMatrix.Infrastructure/Identity/` | `ApplicationUser` |
| DI extensions | layered-dotnet: `<Layer>/DependencyInjection.cs` | `Add<Layer>(this IServiceCollection, ...)` |
| Controllers | layered-dotnet: `SpeakingMatrix.Api/Controllers/` | `<Name>Controller : ControllerBase`, `[ApiController]` |
| Configuration | layered-dotnet: `SpeakingMatrix.Api/appsettings*.json` (no secrets) + user-secrets | section keys `Jwt:*`, `ConnectionStrings:*` |
| Architecture decisions | `services/api/docs/architecture/` | `<topic>.md` |
| Screens and UI components | vite-react-spa: `apps/web/src/components/` | `PascalCase.jsx`, default export |
| App state + screen switching | vite-react-spa: `apps/web/src/App.jsx` | — |
| Browser-API wrappers / hooks | vite-react-spa: `apps/web/src/hooks/` | `useX.js` |
| Static/sample data | vite-react-spa: `apps/web/src/data/` | `camelCase.js`, named exports |
| UI copy (FB2) | vite-react-spa: no catalogue yet — new feature copy goes in a copy module in `apps/web/src/data/` | `<feature>Copy.js`, named export |
| Design tokens / global CSS utilities | vite-react-spa: `tailwind.config.js`, `src/index.css` | kebab-case classes |
| Tests | none exist in either app | — |

## Idioms

**Layer DI extension** (`SpeakingMatrix.Infrastructure/DependencyInjection.cs`):

```csharp
public static IServiceCollection AddInfrastructure(this IServiceCollection services, IConfiguration configuration)
{
    var connectionString = configuration.GetConnectionString("DefaultConnection")
        ?? throw new InvalidOperationException("Connection string 'DefaultConnection' is not configured.");
    services.AddDbContext<ApplicationDbContext>(o => o.UseSqlServer(connectionString));
    return services;
}
```

**Controller** (`SpeakingMatrix.Api/Controllers/`):

```csharp
[ApiController]
[Route("[controller]")]
public class LessonsController : ControllerBase { ... }
```

**Presentational component** (`apps/web/src/components/`):

```jsx
export default function Toast({ message, visible }) {
  return <div className={`... ${visible ? 'toast-enter' : 'hidden'}`}>{message}</div>;
}
```

**Overlay closed by state** (`SentenceDrawer.jsx`, `SpeakingSheet.jsx`):

```jsx
if (!open) return null;
return (<><div onClick={onClose} className="fixed inset-0 bg-black/70 backdrop-blur-md z-40" /> ... </>);
```

**Static data module** (`apps/web/src/data/lessons.js`):

```js
export const lessonsData = [{ id: 1, title: '...', total: 10, completed: 3, status: 'learning' }];
```

## Pre-Write Checklist

Run before **every** file save; if any answer is "no", fix it before saving —
do NOT add a TODO for it:

- [ ] Layout family identified (layered-dotnet / vite-react-spa) and the file goes to that family's path?
- [ ] No cross-import between `apps/web` and `services/api`; no invented endpoint or contract (P5)?
- [ ] B1 — every literal with business meaning is a named constant or config key?
- [ ] B2 / P2 — no secret in source or appsettings; required config throws when missing?
- [ ] B3 — no swallowed exception or ignored promise?
- [ ] P1 — persistence/Identity code and migrations only in Infrastructure, SQL Server only?
- [ ] P3 — new services registered in the layer's `DependencyInjection` extension, not `Program.cs`?
- [ ] FE1 — styles use Tailwind + glass tokens/`index.css` utilities and match `specs/prototype.html`?
- [ ] FE2 — shared state stays in `App.jsx`, components get props + `on*` callbacks?
- [ ] FE3 — browser APIs go through `src/hooks/` with a capability guard?
- [ ] B6 — every comment ≤3 lines, says why not what, none narrate the change?
- [ ] B7 — every new file is reused, mandated by a placement row/toolchain, or split for readability — single-use types, constants and one-impl interfaces sit with their consumer?
- [ ] FB1 — each new component file is reused, owns state, or was split because the parent became hard to read — not because it was a design frame?
- [ ] FB2 — no string, value or option list from the design frame is a literal in this component (copy → copy module/i18n, samples → fixture)?
- [ ] Build passes: `npm run build` in `apps/web` / `dotnet build` of `SpeakingMatrix.slnx`?
